# 무인 헤지펀드급 운영 고도화 계획

> 최신 기준(2026-05-31): Atlas Investment은 토스증권 공식 API 출시 전 안전한 PAPER/DRY_RUN 운용 OS입니다. 완성된 글로벌 헤지펀드 또는 실거래 봇으로 판정하지 않습니다. 토스 플랫폼 범위는 KR/US 주식·ETF·채권·미국주식 옵션 중심이며, 직접 선물·현물 FX·직접 원자재 거래는 공식 지원 전까지 제외합니다. 실거래는 공식 API adapter 구현, read-only reconciliation, 30일 heartbeat, promotion evidence 통과 후에만 검토합니다.

작성일: 2026-05-31

## 목표

Atlas Investment의 최종 목표는 한국/미국 주식, ETF, 외환 노출, 단기/스윙/장기/리밸런싱/퀀트 전략을 하나의 안전한 무인 운용 체계로 묶는 것이다.

단, 무인 자동 실거래는 기술 기능만으로 켤 수 없다. 아래 네 가지가 모두 통과되어야 한다.

1. 공식 브로커 주문 API와 실시간 시세/체결 API
2. 계좌, 주문, 체결, 잔고 reconciliation
3. 데이터 품질, 리스크, 거버넌스, 감사 로그
4. 수동 승인된 라이브 승격 절차와 킬스위치

토스증권 공식 실주문 API 문서와 승인된 키가 확인되기 전까지 `LIVE_AUTO` 주문은 계속 차단한다.

## 현재 단계 판정

현재 Atlas Investment은 실거래 전 운영 관찰성이 강화된 PAPER/DRY_RUN 플랫폼이다.

이미 갖춘 것:

- git 변경 이력 관리
- HTML 운영 대시보드
- DART 공시 이벤트 신호
- sample/yfinance/hybrid 데이터 갱신 루틴
- Toss read-only 스냅샷 경로
- 비용 정책, ETF 비용 최적화, 멀티통화 회계 골격
- 주문 상태 머신, 전략 검증, 포트폴리오 백테스트
- 미수/신용 하드 차단

아직 실전 승격 전 보강할 것:

- 실계좌 기반 포트폴리오 truth source
- 주문 합산 리스크와 일일 총량 관리
- 백테스트 look-ahead bias 제거
- 실시간 이벤트 루프와 장애 복구
- 데이터 공급원 품질 보증
- 자동 운용 승인/중지/재개 워크플로우

## Phase A: 운영 안전 기반

목표: 프로그램이 계속 돌아도 저장소와 운영 데이터가 오염되지 않게 한다.

구현/정책:

- 운영 산출물은 git에서 제외한다.
- `data/reports`, `data/lake`, `data/orders`, `data/toss_readonly`, 외부 OHLCV 캐시는 커밋하지 않는다.
- `.env`와 API 키는 절대 커밋하지 않는다.
- `sample` 데이터 갱신은 기본적으로 네트워크 호출을 하지 않는다.
- 네트워크 호출은 `--include-kr-snapshots`, `--vendor yfinance`, `--vendor hybrid`처럼 명시된 경우에만 수행한다.

승격 기준:

- 테스트와 스모크 실행 후 `git status`가 코드 변경 외 운영 산출물로 더러워지지 않는다.
- 오프라인 모드가 네트워크 없이 반복 실행된다.

## Phase B: 데이터 엔진

목표: 샘플 데이터 의존을 줄이고, 실제 운용 가능한 데이터 레이크를 만든다.

필수 구성:

- 전체 KRX/US 종목 마스터
- 상장폐지/거래정지/관리종목/ETF/ETN 상태
- survivorship-bias-free 과거 가격
- 배당, 액면분할, 권리락, 환율, 휴장일
- 데이터 공급원별 freshness, checksum, row count, 결측률
- yfinance fallback은 연구용으로만 표시

승격 기준:

- 모든 종목 데이터에 `source`, `as_of`, `quality_status`, `checksum`이 있다.
- 누락/지연/이상치가 자동으로 `degraded` 또는 `blocked` 처리된다.

## Phase C: 전략 연구소

목표: 전략을 많이 넣는 것이 아니라, 살아남을 전략만 PAPER로 승격한다.

필수 검증:

- in-sample/out-of-sample 분리
- walk-forward 검증
- Monte Carlo 경로 시뮬레이션
- 거래비용/슬리피지/세금/환전 비용 반영
- 시장 국면별 성과 분해
- 과최적화 경고
- 벤치마크 대비 성과

승격 기준:

- 전략별 승인 상태: `research`, `paper_candidate`, `paper_approved`, `live_candidate`, `live_approved`
- `live_approved`는 수동 승인 없이는 불가능하다.

## Phase D: 리스크 엔진

목표: 주문 1건이 아니라 하루 전체 운용 상태를 통제한다.

필수 보강:

- 주문 합산 현금 소진 검사
- 일일 총 주문금액 한도
- 일일 손실 한도
- 종목/섹터/국가/통화/레버리지 총량 한도
- 보유 종목 수 증가 검사
- 주문 전후 포트폴리오 시뮬레이션
- 킬스위치 파일/환경변수/CLI 3중화

승격 기준:

- 주문 후보 전체를 하나의 batch로 검증한다.
- batch 통과 전에는 어떤 브로커 라우트도 호출하지 않는다.

## Phase E: 실행 엔진

목표: 주문 제출보다 주문 상태 일관성이 먼저다.

필수 보강:

- idempotency key
- 주문 생성, 검증, 큐, 제출, 부분체결, 체결, 취소, 거부, 만료 상태
- 브로커 주문 ID와 내부 주문 ID 매핑
- 재시도 정책
- 중복 주문 방지
- 장 시작/장 마감/휴장일/서킷브레이커 처리
- 실시간 체결 이벤트 reconciliation

승격 기준:

- 장애 후 재시작해도 주문 상태가 복구된다.
- 브로커 상태와 내부 상태가 불일치하면 신규 주문을 차단한다.

## Phase F: 무인 운영 루프

목표: cron 수준을 넘어 항상 켜진 운영 데몬으로 발전시킨다.

필수 구성:

- 장전 데이터 갱신
- 장전 리스크 프리플라이트
- 장중 실시간 이벤트 처리
- 장중 헬스체크
- 마감 reconciliation
- 마감 리포트
- 장애 알림
- 자동 복구와 수동 개입 요청 분리

승격 기준:

- 장애는 `ok`, `degraded`, `blocked`, `manual_review_required`로 분류된다.
- `blocked` 상태에서는 신규 주문이 불가능하다.

## Phase G: 거버넌스와 감사

목표: 나중에 왜 샀고 왜 팔았는지 복원 가능해야 한다.

필수 기록:

- 데이터 버전
- 전략 버전
- 신호 입력값
- 투자위원회 메모
- 리스크 검증 결과
- 주문 의도
- 브로커 응답
- 체결 결과
- 변경 승인자/시각

승격 기준:

- 모든 거래는 재현 가능한 감사 묶음으로 남는다.
- 감사 로그에는 API 키, 계좌번호 원문, 토큰을 저장하지 않는다.

## Phase H: 라이브 승격 절차

목표: 실거래는 작은 금액, 좁은 범위, 강한 차단으로 시작한다.

승격 순서:

1. DRY_RUN 30영업일 무장애
2. PAPER 30영업일 무장애
3. read-only 계좌 reconciliation 10영업일 성공
4. 소액 수동 승인 주문 5회
5. 소액 자동 주문 20회
6. 한도 확대 심사

절대 금지:

- 미수
- 신용
- 비공식/리버스엔지니어링 주문 API
- reconciliation 실패 상태의 신규 주문
- `manual_review_required` 상태의 자동 주문

## 최종 원칙

완벽한 무인 운용은 "주문을 자동으로 넣는 것"이 아니다. 데이터, 리스크, 실행, 복구, 감사가 모두 자동으로 실패를 감지하고 멈출 수 있어야 한다.

Atlas Investment은 이 원칙에 따라 먼저 멈출 줄 아는 시스템으로 만든 뒤, 공식 API와 충분한 검증이 갖춰졌을 때만 실거래 범위를 넓힌다.
