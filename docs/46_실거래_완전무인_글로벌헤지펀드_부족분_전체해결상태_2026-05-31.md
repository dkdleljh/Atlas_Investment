# 46. 실거래 완전무인 글로벌 헤지펀드 부족분 전체 해결 상태

> 최신 기준(2026-05-31): Atlas Investment은 토스증권 공식 API 출시 전 안전한 PAPER/DRY_RUN 운용 OS입니다. 완성된 글로벌 헤지펀드 또는 실거래 봇으로 판정하지 않습니다. 토스 플랫폼 범위는 KR/US 주식·ETF·채권·미국주식 옵션 중심이며, 직접 선물·현물 FX·직접 원자재 거래는 공식 지원 전까지 제외합니다. 실거래는 공식 API adapter 구현, read-only reconciliation, 30일 heartbeat, promotion evidence 통과 후에만 검토합니다.

## 1. 목적

사용자는 “실거래 가능한 완전 무인 글로벌 헤지펀드”가 되기 위해 부족한 부분을 전부 문서화하고, 가능한 것은 전부 해결하라고 요청했다.

이 문서는 부족분을 다음 두 종류로 분리한다.

- 코드/문서/테스트로 지금 해결 가능한 항목
- 공식 API, 계좌 권한, 데이터 계약, 실제 운용 기간처럼 외부 실체가 있어야 완료되는 항목

## 2. 공식 공개 정보 확인

2026-05-31 KST 기준 공식/준공식 웹 검색 결과:

- Toss Securities 공식 사이트는 국내/해외 주식, ETF, 해외 채권, 미국주식 옵션 등 투자 상품 표면을 설명하지만, 실주문 자동화용 공개 Open API 문서를 제공하는 페이지는 확인되지 않았다.
- Toss Securities US 사이트는 미국 broker-dealer 소개와 투자위험 고지를 제공하지만, Atlas Investment에 바로 연결할 수 있는 한국 토스증권 실주문 API 문서는 아니다.
- 검색되는 Toss Open API 문서는 토스플레이스, 토스쇼핑, 토스페이먼츠 등 결제/상점/쇼핑 도메인 문서이며, 토스증권 주식 주문 API 문서가 아니다.

따라서 `TossLiveBroker`는 계속 placeholder 상태가 맞다. 결제/쇼핑/토스플레이스 API를 증권 주문 API로 대체 사용하지 않는다.

## 3. 이번 추가 해결 항목

### 3.1 Read-only snapshot 범위 확대

수정 파일:

- `src/atlas_investment/brokers/toss_readonly.py`

해결 내용:

- 기존 read-only sync는 account, positions, allocation만 저장했다.
- 이제 open orders와 fills 스냅샷도 수집 대상에 포함한다.
- 경로는 다음과 같다.
  - `data/toss_readonly/account_summary.json`
  - `data/toss_readonly/account.json`
  - `data/toss_readonly/positions.json`
  - `data/toss_readonly/allocation.json`
  - `data/toss_readonly/open_orders.json`
  - `data/toss_readonly/fills.json`

주의:

- 현재 `tossctl`이 없으므로 실제 수집은 blocked가 정상이다.
- 이 구현은 주문을 보내지 않고 read-only 명령만 호출한다.

### 3.2 Reconciliation 범위 확대

수정 파일:

- `src/atlas_investment/ops/reconciliation.py`
- `src/atlas_investment/cli.py`

해결 내용:

- 내부 filled 포지션과 broker positions 비교
- 내부 submitted/partially_filled/cancel_requested 주문과 broker open orders 비교
- 내부 filled 주문과 broker fills 비교
- `account.json`과 `account_summary.json` fallback 지원
- `cash_by_currency`, `balances`, `cash_balances`, `cash_krw`, `cash_usd` 형태의 통화별 현금 추출 지원
- CLI `reconciliation-check` 결과에 open order/fill/cash currency count 노출

효과:

- 실거래 승격 전 포지션뿐 아니라 미체결 주문, 체결, 현금까지 대사할 준비가 됐다.
- broker 스냅샷이 없으면 여전히 blocked가 맞다.

### 3.3 테스트 보강

수정 파일:

- `tests/test_integrations.py`
- `tests/test_phase20.py`

추가 검증:

- Toss read-only sync가 `account.json`, `open_orders.json`, `fills.json`을 저장하는지 확인
- reconciliation이 `account_summary.json` fallback을 읽는지 확인
- queued 주문을 broker position과 비교하지 않는지 확인

- USD PAPER 체결이 KRW 현금으로 정규화되는지 확인

## 5. 남은 부족분과 완료 조건

### 5.1 공식 실거래 브로커 API

현재 상태:

- blocked
- `TossLiveBroker`는 placeholder
- 공식 토스증권 주문 API 문서, REST/WebSocket URL, credential, 계좌 ID 없음

완료 조건:

- 공식 문서 URL이 토스증권 공식 도메인에서 확인됨
- 주문, 취소, 정정, 미체결, 체결, 잔고, 포지션, 계좌 현금, 실시간 quote/fill endpoint 확인
- app key, app secret, account ID가 안전하게 등록됨
- sandbox 또는 소액 실주문 trial 통과
- API rate limit, idempotency, 장애 응답 코드, 장중 세션 규칙이 문서화됨

완료 후 작업:

- `TossLiveBroker` adapter 구현
- 주문 제출 전 `readiness`, `reconciliation`, `promotion-evidence`를 모두 확인
- 첫 live order는 자동이 아니라 수동 승인 후 소액 trial로만 실행

### 5.2 Read-only 계좌 대사

## 6. 운영 runbook

### 6.1 공식 API 수령 시

1. 공식 문서 도메인과 문서 버전을 기록한다.
2. `TOSS_API_DOCS_URL`, REST URL, WebSocket URL, key/secret/account를 `.env` 또는 안전한 secret store에 등록한다.
3. `readiness`가 `manual_review_required` 이상으로 바뀌는지 확인한다.
4. `TossLiveBroker` adapter를 구현한다.
5. 주문 전송 없이 account/quote/order schema smoke test를 먼저 수행한다.
6. read-only reconciliation 10영업일을 먼저 통과한다.
7. 소액 주문 trial을 수동 승인 후 수행한다.
8. manual approval JSON을 저장한다.
9. live order size cap을 극소액으로 시작한다.

### 6.2 Reconciliation 차이 발생 시

1. 신규 주문을 차단한다.
2. 차이 종류를 분류한다: cash, position, open_order, fill.
3. broker snapshot 원본과 내부 order state를 보존한다.
4. 차이 원인을 문서화한다.
5. 차이가 해결되기 전 promotion evidence를 기록하지 않는다.

### 6.3 데이터 장애 발생 시

1. 해당 시장/자산군 신규 주문을 차단한다.
2. stale data 여부를 dashboard와 alert로 표시한다.
3. fallback provider가 공식 권리 범위 내인지 확인한다.
4. 복구 후 freshness audit를 재실행한다.

## 7. 결론

이번 작업으로 Atlas Investment의 내부 코드 부족분 중 즉시 해결 가능한 항목은 추가로 보강했다.

- read-only sync 범위 확대
- open orders/fills/cash reconciliation 준비
- CLI reconciliation 출력 확대
- 관련 테스트 추가

하지만 실거래 가능한 완전 무인 글로벌 헤지펀드 판정은 여전히 불가능하다. 남은 19개 blocker는 코드로 가짜 해결할 수 없는 외부 API, 데이터 권리, 실제 계좌 스냅샷, 운용 시간, 승격 승인이다.

따라서 현재 올바른 상태는 다음이다.

- 내부 구현 가능 blocker: 0
- 외부 실체/증거 blocker: 19
- live 자동매매: blocked
- PAPER/DRY_RUN 운용 OS: 강화 완료
