# 43. 토스 공식 API 대기 상태에서 가능한 실거래 준비 인프라 구현

> 최신 기준(2026-05-31): Atlas Investment은 토스증권 공식 API 출시 전 안전한 PAPER/DRY_RUN 운용 OS입니다. 완성된 글로벌 헤지펀드 또는 실거래 봇으로 판정하지 않습니다. 토스 플랫폼 범위는 KR/US 주식·ETF·채권·미국주식 옵션 중심이며, 직접 선물·현물 FX·직접 원자재 거래는 공식 지원 전까지 제외합니다. 실거래는 공식 API adapter 구현, read-only reconciliation, 30일 heartbeat, promotion evidence 통과 후에만 검토합니다.

> 구현일: 2026-05-31 KST
>
> 목표: 토스증권 공식 API가 나오면 바로 붙일 수 있게 live broker 경계는 유지하고, 그 외 내부 인프라는 실거래 승격 준비 수준으로 보강한다.

## 1. 전제

실주문 전송은 여전히 차단한다. 이번 작업은 공식 API 없이도 구현 가능한 영역만 다룬다.

- 공식 주문 API adapter는 `TossLiveBroker` placeholder로 유지
- `LIVE_AUTO` 실주문은 계속 blocked
- 데이터 권리, 실제 계좌 스냅샷, 30일 운용 증거는 fake로 만들지 않음
- DRY_RUN/PAPER에서 검증 가능한 인프라를 먼저 강화

## 2. 구현한 항목

### 2.1 글로벌 갭 감사 CLI

추가 파일:

- `src/atlas_investment/ops/global_gap.py`

추가 CLI:

```bash
.venv/bin/python -m atlas_investment.cli global-gap-audit
```

기능:

- hedgefund readiness
- data entitlements
- promotion evidence
- reconciliation
- heartbeat

위 항목을 하나로 합쳐 내부 구현으로 줄일 수 있는 blocker와 외부 의존 blocker를 분리한다.

검증 결과:

```json
{
  "status": "blocked",
  "blocked": 19,
  "degraded": 1,
  "code_possible_blockers": 9,
  "external_blockers": 10
}
```

해석:

- 아직 blocked가 많다.
- 다만 `code_possible_blockers`를 이제 기계적으로 추적할 수 있다.
- 외부 API/데이터/증거 blocker와 내부 구현 blocker를 섞어 보지 않게 됐다.

### 2.2 promotion evidence 기록기

수정 파일:

- `src/atlas_investment/ops/promotion.py`

추가 CLI:

```bash
.venv/bin/python -m atlas_investment.cli promotion-evidence-record --evidence-kind dry_run --status blocked --source smoke-test
```

지원 evidence kind:

- `dry_run`
- `paper`
- `reconciliation`
- `small_order`

중요 정책:

- `status=ok`일 때만 승격 증거에 반영한다.
- blocked/degraded 상태는 로그만 남기고 일수에 더하지 않는다.
- fake evidence를 만들지 않는다.
- 실제 `ok` 기록은 daemon 또는 사람이 확인한 실제 운용 성공일 때만 남긴다.

검증 결과:

```json
{
  "status": "blocked",
  "kind": "dry_run",
  "recorded": false,
  "reason": "status가 ok가 아니므로 승격 증거에 반영하지 않았습니다."
}
```

이 결과는 의도한 동작이다. blocked 상태를 승격 증거로 세지 않았다.

### 2.3 포트폴리오 최적화 엔진

추가 파일:

- `src/atlas_investment/portfolio/optimizer.py`

추가 CLI:

```bash
.venv/bin/python -m atlas_investment.cli portfolio-optimizer --optimizer-method risk_parity
```

지원 방식:

- `risk_parity`
- `inverse_vol`
- `equal_weight`
- `vol_target`

기능:

- 후보별 연율화 변동성 계산
- ADV 기반 capacity notional 계산
- 목표 변동성 기반 노출 축소
- 종목 최대 비중 제한
- 총 gross exposure 제한

검증 결과:

```json
{
  "status": "blocked",
  "method": "risk_parity",
  "position_count": 0,
  "gross_exposure": 0.0,
  "warnings": ["매수 후보가 없습니다."]
}
```

이 결과는 오류가 아니다. 현재 엄격한 quant ensemble 기준에서는 buy 후보가 없어서 포트폴리오를 만들지 않았다. 실거래 준비 시스템에서는 신호가 약할 때 억지 매수를 하지 않는 것이 맞다.

### 2.4 PAPER child-order 상태머신

추가 파일:

- `src/atlas_investment/execution/child_orders.py`

추가 CLI:

```bash
.venv/bin/python -m atlas_investment.cli child-order-sim --mode paper --algorithm vwap --symbol 005930 --slices 4 --limit 8
```

기능:

- TWAP/VWAP/POV 상위 계획을 child order lifecycle로 변환
- PAPER에서는 filled/partially_filled 시뮬레이션
- DRY_RUN에서는 validated까지만 진행
- LIVE_AUTO는 계속 blocked
- 부분체결 fill ratio 시나리오 지원

검증 결과:

```json
{
  "status": "simulated",
  "mode": "paper",
  "algorithm": "vwap",
  "planned_slices": 4,
  "filled_slices": 4,
  "planned_quantity": 8.0,
  "filled_quantity": 8.0
}
```

## 4. 현재 남은 blocker

이번 구현으로 내부 인프라는 더 좋아졌지만, 다음은 여전히 외부 조건 또는 장기 운용 증거가 필요하다.

- 토스 공식 live order API
- 공식 실시간 quote/fill/order stream
- 미체결 정정/취소
- 실제 read-only broker snapshot
- licensed global data entitlement
- full global instrument master
- 30영업일 DRY_RUN/PAPER evidence
- 10영업일 reconciliation evidence
- 소액 실주문 trial
- 수동 live promotion approval

## 6. 판단

Atlas Investment은 이제 토스 공식 API가 나오면 live broker adapter를 붙일 수 있는 주변 인프라가 더 단단해졌다. 다만 실주문은 계속 차단 상태가 맞다. 이번 작업의 의미는 실거래를 억지로 켠 것이 아니라, 실거래로 넘어가기 전 필요한 내부 검증, 최적화, 집행, 증거 누적 구조를 더 명확히 만든 것이다.
