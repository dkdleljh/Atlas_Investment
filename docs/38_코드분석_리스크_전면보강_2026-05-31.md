# 코드분석 리스크 전면보강 기록

> 최신 기준(2026-05-31): Atlas Investment은 토스증권 공식 API 출시 전 안전한 PAPER/DRY_RUN 운용 OS입니다. 완성된 글로벌 헤지펀드 또는 실거래 봇으로 판정하지 않습니다. 토스 플랫폼 범위는 KR/US 주식·ETF·채권·미국주식 옵션 중심이며, 직접 선물·현물 FX·직접 원자재 거래는 공식 지원 전까지 제외합니다. 실거래는 공식 API adapter 구현, read-only reconciliation, 30일 heartbeat, promotion evidence 통과 후에만 검토합니다.

## 목적

2026-05-31 코드 분석에서 확인한 운영 승격 전 핵심 리스크를 보강했다.

보강 대상은 다음과 같다.

- USD/KRW 회계 및 주문금액 정규화
- 백테스트 신호 체결과 stop-loss/take-profit 시간축
- 기존 레버리지/인버스 보유분을 포함한 배치 리스크
- daemon heartbeat의 blocked/degraded 상태 반영
- read-only reconciliation의 수량/현금 스냅샷 검사
- CLI dispatch 복잡도 완화

## 구현 내용

### 1. KRW 기준 주문금액 정규화

추가 파일:

- `src/atlas_investment/fx/conversion.py`

`FxRates`와 `quote_price_krw()`를 추가해 quote currency가 USD인 경우에도 주문금액을 KRW로 환산한 뒤 리스크를 검사한다.

적용 위치:

- `src/atlas_investment/orders/planner.py`
- `src/atlas_investment/risk/engine.py`
- `src/atlas_investment/risk/batch.py`
- `config/risk_policy.json`

정책에는 `usdkrw_reference_rate`를 추가했다. 기본값은 1380.0이다.

### 2. 백테스트 시간축 재정렬

`src/atlas_investment/backtest/engine.py`를 수정했다.

기존에는 신호가 현재 봉에서 발생하면 다음 봉 open 가격으로 체결가를 잡으면서도, 같은 루프 안에서 현재 봉 close 기준 stop/take-profit이 평가될 수 있었다.

수정 후 구조:

1. 예약된 신호를 해당 execution bar open에서 먼저 체결
2. 이미 보유 중인 포지션에 대해서만 현재 bar close 기준 stop/take-profit 평가
3. 현재 bar close 기준 새 신호를 생성하고 미래 execution bar로 예약

이제 미래 open 체결 후 과거 close로 손절/익절되는 시간축 오류를 막는다.

### 3. 기존 레버리지/인버스 포지션 포함 배치 리스크

`src/atlas_investment/risk/batch.py`를 보강했다.

기존에는 현재 주문 목록에 포함된 심볼만 레버리지/인버스 여부를 알 수 있어, 이미 보유 중인 TQQQ/SQQQ 같은 포지션이 현재 주문에 없으면 aggregate leveraged/inverse weight에서 빠질 수 있었다.

수정 후 `assets_by_symbol`을 받아 기존 포지션의 레버리지/인버스 여부도 계산한다.

`TradingEngine.run_once()`는 runtime universe를 `assets_by_symbol`로 넘긴다.

### 4. daemon heartbeat 상태 반영

`scripts/atlas_investment_daemon.sh`를 수정했다.

기존 daemon은 CLI exit code만 보았다. Atlas Investment CLI는 blocked 리포트를 JSON으로 반환해도 프로세스 exit code는 0일 수 있으므로 heartbeat가 `ok`로 기록될 수 있었다.

수정 후 daemon은 각 명령의 JSON에서 `overall_status` 또는 `status`를 읽고, 가장 심각한 상태를 heartbeat에 기록한다.

상태 우선순위:

1. `blocked`
2. `degraded`
3. `ok`

검증 결과 restart 후 heartbeat가 `blocked`로 기록됐다.

### 5. read-only reconciliation 확장

`src/atlas_investment/ops/reconciliation.py`를 보강했다.

기존 검사는 심볼 존재 여부 중심이었다. 수정 후 다음을 추가로 확인한다.

- 내부 filled 주문 기준 순포지션 수량
- broker read-only positions 수량
- 포지션 수량 불일치
- account snapshot의 KRW 현금 필드 파싱 가능 여부

아직 완전한 broker-grade reconciliation은 아니다. 체결 ID, 평균단가, pending order, 부분체결, 취소/거절 상태까지 맞추려면 Toss 공식 read-only 스냅샷 스키마가 필요하다.

### 6. CLI dispatch 정리

`src/atlas_investment/cli.py`의 긴 if-chain dispatch를 handler mapping 방식으로 바꿨다.

아직 CLI 파일 자체는 크다. 다만 명령 라우팅은 더 읽기 쉬운 형태가 되었고, 다음 단계에서 `cli_ops.py`, `cli_data.py`, `cli_broker.py`, `cli_research.py`로 분리하기 쉬워졌다.

## 현재 상태 판단

이번 보강으로 분석에서 지적한 즉시 수정 가능한 코드 리스크는 대부분 처리됐다.

남은 큰 항목은 코드만으로 완료할 수 없다.

- licensed survivorship-bias-free market data
- Toss 공식 order/read-only API 스키마
- 실제 broker reconciliation 10거래일 증빙
- 30일 heartbeat 증빙
- live promotion approval
- 공식 adapter 구현 후 소액 주문 검증

따라서 Atlas Investment의 올바른 판정은 계속 다음과 같다.

```text
PAPER/DRY_RUN 운용 OS: 강화됨
실계좌 자동매매: blocked
글로벌 무인 헤지펀드: blocked
```
