# 부족분 통합 보강 기록

> 최신 기준(2026-05-31): Atlas Investment은 토스증권 공식 API 출시 전 안전한 PAPER/DRY_RUN 운용 OS입니다. 완성된 글로벌 헤지펀드 또는 실거래 봇으로 판정하지 않습니다. 토스 플랫폼 범위는 KR/US 주식·ETF·채권·미국주식 옵션 중심이며, 직접 선물·현물 FX·직접 원자재 거래는 공식 지원 전까지 제외합니다. 실거래는 공식 API adapter 구현, read-only reconciliation, 30일 heartbeat, promotion evidence 통과 후에만 검토합니다.

작성일: 2026-05-30

## 목적

이 문서는 이전 재검증에서 남은 API 제외 보강 과제를 코드에 반영한 기록이다.

토스증권 공식 실주문 API, 실시간 호가/체결 API, 실제 계좌 reconciliation처럼 외부 연결 없이는 완성할 수 없는 영역은 여전히 차단 상태로 둔다. 대신 API 없이 구현 가능한 비용 정책, 런타임 유니버스 선택, 주문 상태 추적, 비용 리포트, 테스트를 보강했다.

## 구현한 내용

### 1. 비용 정책과 펀드 보수 모델

추가 파일:

```text
config/cost_policy.json
src/atlas_investment/cost_policy.py
```

구현 범위:

- 한국장/미국장별 수수료
- 슬리피지
- 매도 거래세
- 환전 스프레드
- 운용보수 일할 계산
- 보관/관리비 일할 계산
- 성과보수 high-water mark/hurdle rate 계산 틀
- `cost-report` CLI

관련 명령:

```bash
.venv/bin/python -m atlas_investment.cli cost-report --initial-cash 100000000 --ending-equity 103000000 --days 30
```

### 2. 백테스트 비용 정책 연결

`BacktestEngine`에 `from_cost_policy()`를 추가했다.

이제 `backtest` CLI는 `config/cost_policy.json`이 있으면 해당 정책의 시장별 비용률을 사용한다.

구현 위치:

```text
src/atlas_investment/backtest/engine.py
src/atlas_investment/cli.py
```

### 3. 런타임 유니버스 선택 개선

기존 기본 운용 루프는 작은 샘플 유니버스에 고정되어 있었다. 이제 `data/lake/instrument_master.json`, `data/universe/instrument_master.json`, 내장 샘플 유니버스를 비교해 tradable 자산 수가 가장 넓은 후보를 선택한다.

stale data lake master가 2종목처럼 작게 남아 있어도 전체 운용 루프가 그쪽으로 축소되지 않도록 방어했다.

구현 위치:

```text
src/atlas_investment/data/universe.py
src/atlas_investment/engine.py
src/atlas_investment/cli.py
```

### 4. 주문 상태 머신을 기본 운용 루프에 연결

기존 주문 상태 머신은 smoke command 중심이었다. 이제 기본 `run` 경로에서 주문 후보마다 상태를 기록한다.

연결된 상태:

```text
created
validated
queued
submitted
filled
blocked
```

PAPER 모드는 `created -> validated -> queued -> submitted -> filled` 흐름을 남긴다.

DRY_RUN 모드는 실제 체결 없이 `created -> validated -> queued`까지만 남긴다.

리스크 차단 주문은 `blocked`로 남긴다.

저장 위치:

```text
data/orders/runtime_order_state_store.json
```

### 5. 테스트 보강

테스트가 43개에서 45개로 증가했다.

추가 검증:

- 펀드 보수 모델이 운용보수/관리비를 계산하는지
- stale 소형 data lake master가 기본 운용 유니버스를 축소하지 않는지
- `cost-report` CLI가 정상 실행되는지

## 검증 결과

실행한 검증:

```text
.venv/bin/python -m compileall -q src tests
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python -m atlas_investment.cli cost-report --initial-cash 100000000 --ending-equity 103000000 --days 30
.venv/bin/python -m atlas_investment.cli --mode dry_run --once
.venv/bin/python -m atlas_investment.cli --mode paper --once
.venv/bin/python -m atlas_investment.cli backtest --symbol 005930 --strategy moving_average_cross --days 180
.venv/bin/python -m atlas_investment.cli order-state-smoke --symbol 005930
.venv/bin/python -m atlas_investment.cli healthcheck
.venv/bin/python -m atlas_investment.cli phase20-audit
```

결과:

```text
compileall 통과
unittest 45개 통과
cost-report ok
DRY_RUN ok
PAPER ok
backtest 정상
order-state-smoke queued
healthcheck ok
phase20-audit blocked
```

`phase20-audit blocked`는 정상이다. 토스 공식 실주문 API가 없기 때문에 라이브 주문 준비 완료로 표시하지 않는다.

## 아직 남은 외부 의존 항목

- 실제 계좌/잔고/주문/체결 reconciliation
- `tossctl` read-only 로그인 경로
- DART `API_K_DART`
- 전체 시장 survivorship-bias-free 데이터
- 배당/분할/상폐/corporate action 보정 데이터

## 현재 판정

API 제외 기준으로는 비용, 유니버스, 상태 추적 쪽의 큰 구조적 빈틈을 보강했다.

다만 실거래 자동운용으로 승격하려면 공식 API 공개 후 다음 순서가 필요하다.

1. `TossLiveBroker` 공식 문서 기반 구현
2. 실시간 호가/체결 WebSocket 연결
3. 주문 제출/정정/취소 idempotency 검증
4. 실제 계좌 reconciliation
5. 최소 1-3개월 PAPER 운영 리포트 축적
6. 수동 승인 후 소액 실거래 검증
