# 45. 핵심 한계 해결 시도 및 실거래 완전자동화 정직한 최종 기록

> 최신 기준(2026-05-31): Atlas Investment은 토스증권 공식 API 출시 전 안전한 PAPER/DRY_RUN 운용 OS입니다. 완성된 글로벌 헤지펀드 또는 실거래 봇으로 판정하지 않습니다. 토스 플랫폼 범위는 KR/US 주식·ETF·채권·미국주식 옵션 중심이며, 직접 선물·현물 FX·직접 원자재 거래는 공식 지원 전까지 제외합니다. 실거래는 공식 API adapter 구현, read-only reconciliation, 30일 heartbeat, promotion evidence 통과 후에만 검토합니다.

## 1. 요청

요청 내용:

- 핵심 한계를 완벽하게 해결
- 실거래 가능한 완전 무인 글로벌 헤지펀드로 완벽하게 구현
- 관련 과정과 결과를 문서로 남김

## 2. 최종 판정

Atlas Investment을 코드만으로 “실거래 가능한 완전 무인 글로벌 헤지펀드”로 판정하지 않는다.

그 이유는 코드 부족만이 아니라, 다음 조건이 실제 외부 상태와 증거를 요구하기 때문이다.

- 토스증권 공식 주문 REST/WebSocket API 문서
- 공식 API credential과 계좌 식별자
- read-only 계좌/포지션/주문/체결 스냅샷
- 라이선스 있는 글로벌 시장 데이터 계약
- survivorship-bias-free instrument master와 corporate action 이력
- 30영업일 DRY_RUN/PAPER 운영 증거
- 10영업일 read-only reconciliation 무차이 증거
- 소액 실주문 trial과 수동 live promotion approval

이 조건을 가짜 파일, 샘플 데이터, 임의 placeholder로 통과 처리하면 시스템은 더 완성되는 것이 아니라 더 위험해진다.

## 3. 이번에 실제로 해결한 내부 한계

### 3.1 PAPER/Mock 브로커 USD 체결 회계 정합성

문제:

- 기존 Mock/PAPER 브로커는 USD 종목 체결 시 USD 가격을 그대로 KRW 현금에서 차감했다.
- 리스크 엔진은 USD/KRW 환산으로 주문 가능 여부를 검사하지만, PAPER 체결 장부는 같은 기준을 쓰지 않았다.

수정:

- `src/atlas_investment/brokers/mock.py`
- USD 체결 금액을 KRW로 정규화해 `cash_krw`와 `market_value`에 반영한다.
- Fill 가격은 원래 거래통화 가격으로 유지하고, 포지션 `currency`도 quote currency를 기록한다.

검증:

- `test_paper_broker_usd_order_normalizes_cash_to_krw` 추가
- AAPL 1주 limit 200 USD 체결 시 KRW 현금이 276,000원 감소하는지 확인한다.

### 3.2 Toss read-only 스냅샷과 reconciliation 파일명 불일치 해결

문제:

- `TossReadOnlyClient.sync_snapshot()`은 `account_summary.json`을 저장했다.
- `ReadOnlyReconciler`는 `account.json`을 기대했다.
- 따라서 read-only sync가 성공해도 reconciliation이 현금 스냅샷을 못 읽을 수 있었다.

수정:

- `src/atlas_investment/brokers/toss_readonly.py`
- account summary 저장 시 `account_summary.json`과 reconciliation용 `account.json`을 함께 저장한다.
- `src/atlas_investment/ops/reconciliation.py`
- `account.json`이 없으면 `account_summary.json`도 읽도록 fallback을 추가했다.

검증:

- `test_toss_readonly_sync_writes_reconciliation_account_alias` 추가
- `test_reconciliation_accepts_account_summary_and_ignores_unfilled_orders_for_positions` 추가

### 3.3 Reconciliation의 PAPER/DRY_RUN 오탐 감소

문제:

- 기존 reconciliation은 `queued`, `submitted`, `filled` 상태를 모두 broker position과 비교했다.
- DRY_RUN/PAPER에서 queued 상태인 주문 후보까지 실계좌 포지션에 있어야 한다고 판단할 수 있었다.

수정:

- broker position reconciliation은 `filled` 내부 주문만 포지션 비교 대상으로 삼는다.
- 미체결 주문 대사는 향후 broker open-order snapshot이 있을 때 별도 비교해야 한다.

효과:

- 포지션 대사는 더 정확해졌다.
- 단, broker snapshot 자체가 없으면 여전히 blocked가 맞다.

### 3.4 주문 상태 저장 원자성 보강

문제:

- `OrderStateStore`는 JSON 파일을 직접 write 했다.
- 프로세스 중단 시 파일이 일부만 써질 가능성이 있었다.

수정:

- `src/atlas_investment/execution/state_machine.py`
- 임시 파일에 먼저 쓰고 `os.replace()`로 원자 교체한다.

효과:

- daemon/PAPER 운용 중 주문 상태 파일 손상 가능성을 줄였다.

### 3.5 Global gap audit의 “코드로 해결 가능” 분류 정직화

문제:

- 글로벌 유니버스, 자산군 커버리지, promotion evidence는 일부 코드로 보강할 수 있지만 최종 통과는 실제 데이터/브로커/운영 증거가 필요하다.
- 이를 `code_possible=true`로 표시하면 샘플 데이터나 임의 증거로 해결 가능한 것처럼 오해할 수 있다.

수정:

- `src/atlas_investment/ops/global_gap.py`
- `global_universe_coverage`, `global_asset_class_coverage`, `read_only_reconciliation`, `autonomy_24x7_daemon`, reconciliation summary, heartbeat summary, promotion evidence 요구사항은 외부 실체/증거/시간이 필요한 blocker로 분류한다.

효과:

- 감사 결과가 더 보수적이고 정직해졌다.
- 내부 구현 가능 blocker와 외부 의존 blocker를 과장 없이 분리한다.

## 4. 여전히 남는 절대 blocker

### 4.1 공식 실거래 브로커

현재 `TossLiveBroker`는 placeholder다. 공식 문서와 credential 없이 실주문 브로커를 구현하지 않는다.

필수 조건:

- 공식 주문 API 문서
- REST/WebSocket endpoint
- quote/order/fill/account/reconciliation endpoint
- cancel/replace
- idempotency key 지원 또는 동등한 중복 방지
- broker 장애/지연/거절 처리
- 소액 실주문 검증

### 4.2 글로벌 데이터 권리

현재 샘플/yfinance 데이터는 연구와 smoke test에는 쓸 수 있지만 기관급 live proof가 아니다.

필수 조건:

- licensed provider
- KR/US/EU/JP/HK/CN/EM 시장 권리
- stock/ETF/bond/future/option/fx/commodity 자산군 권리
- survivorship-bias-free history
- corporate action adjustment
- realtime quote/order book 권리
- freshness SLA

### 4.3 실계좌 reconciliation 증거

현재 내부 장부와 실계좌 스냅샷을 10영업일 무차이로 증명하지 못했다.

필수 조건:

- broker positions
- broker cash
- broker open orders
- broker fills
- 내부 주문 상태와의 대사
- 차이 발생 시 신규 주문 차단

### 4.4 Live promotion evidence

현재 promotion evidence는 blocked가 정상이다.

필수 조건:

- DRY_RUN 30영업일
- PAPER 30영업일
- read-only reconciliation 10영업일
- manual small-order trial
- manual live promotion approval

## 6. 운영 원칙

앞으로도 Atlas Investment은 다음 원칙을 지킨다.

- 공식 API가 없으면 실주문 adapter를 만들지 않는다.
- read-only reconciliation이 없으면 live promotion을 통과시키지 않는다.
- 샘플 데이터로 글로벌 데이터 권리를 대체하지 않는다.
- blocked/degraded 결과를 숨기지 않는다.
- promotion evidence는 실제 `ok` 결과만 센다.
- 미수/신용은 API가 지원해도 금지한다.

## 8. 결론

이번 작업은 “완성된 것처럼 보이게 만드는 작업”이 아니라, 실거래 전 위험한 오탐과 회계 불일치를 줄이고, 남은 blocker를 더 정확하게 드러내는 작업이다.

Atlas Investment은 더 견고한 PAPER/DRY_RUN 운용 OS가 되었지만, 아직 실거래 가능한 완전 무인 글로벌 헤지펀드는 아니다. 이 판정을 유지하는 것이 현재로서는 가장 안전하고 정확하다.
