# 42. 완전 무인 글로벌 헤지펀드/퀀트 부족분 감사

> 최신 기준(2026-05-31): Atlas Investment은 토스증권 공식 API 출시 전 안전한 PAPER/DRY_RUN 운용 OS입니다. 완성된 글로벌 헤지펀드 또는 실거래 봇으로 판정하지 않습니다. 토스 플랫폼 범위는 KR/US 주식·ETF·채권·미국주식 옵션 중심이며, 직접 선물·현물 FX·직접 원자재 거래는 공식 지원 전까지 제외합니다. 실거래는 공식 API adapter 구현, read-only reconciliation, 30일 heartbeat, promotion evidence 통과 후에만 검토합니다.

> 감사일: 2026-05-31 KST
>
> 결론: Atlas Investment은 전략 연구, PAPER/DRY_RUN 운용, 안전 차단, 문서화, 기본 daemon 구조까지는 갖췄지만 아직 완전 무인 자동 운영 초거대 글로벌 헤지펀드/퀀트가 아니다. 현재 상태를 완성으로 표시하지 않는 것이 맞다.

## 3. P0: 완성 전 절대 차단해야 하는 부족분

### 3.1 실거래 브로커가 아직 없다

`src/atlas_investment/brokers/toss.py`의 `TossLiveBroker`는 명시적으로 placeholder다. 생성자에서 RuntimeError를 던지고, portfolio/quote/order/cancel/open_orders/fills 메서드는 전부 미구현이다.

현재 `readiness` 결과:

```json
{
  "status": "blocked",
  "ready_for_live_orders": false,
  "official_docs_verified": false,
  "missing_items": [
    "공식 API 문서 URL",
    "공식 REST API base URL",
    "공식 WebSocket URL",
    "공식 app key",
    "공식 app secret",
    "공식 계좌 식별자"
  ]
}
```

필요한 것:

- 공식 주문 REST API
- 공식 WebSocket 호가/체결 API
- 계좌/잔고/주문/체결 조회 API
- 미체결 정정/취소
- 부분체결 처리
- 주문 거절/만료/재시도 정책
- 브로커 장애 시 kill switch
- 소액 실주문 검증 로그

### 3.2 라이선스 있는 글로벌 데이터가 없다

`data-entitlements` 결과:

```json
{
  "status": "blocked",
  "provider_count": 0,
  "blocked": 6
}
```

현재 감사 기준은 licensed provider, KR/US/EU/JP/HK/CN/EM 시장, stock/ETF/bond/future/option/fx/commodity 자산군, survivorship-bias-free 이력, corporate-action adjustment, realtime data를 요구한다.

필요한 것:

- 유료/계약 기반 시장 데이터
- 상장폐지 포함 survivorship-bias-free 히스토리
- 배당, 액면분할, 병합, 종목코드 변경 반영
- 실시간 호가/체결/주문장 권리
- 글로벌 instrument master
- 데이터 freshness SLA
- 데이터 장애 fallback 정책

### 3.3 실계좌 reconciliation이 없다

`reconciliation-check` 결과:

```json
{
  "status": "blocked",
  "internal_order_count": 104,
  "broker_position_count": 0,
  "internal_position_count": 10,
  "difference_count": 12
}
```

내부 장부는 있지만 실제 브로커 포지션 스냅샷이 없다. 완전 무인 운영에서는 내부 장부와 실계좌가 다르면 즉시 신규 주문을 막아야 한다.

필요한 것:

- read-only 계좌 스냅샷
- 포지션/현금/미체결/체결내역 비교
- 거래통화별 현금 reconciliation
- 배당/세금/수수료 반영
- 차이 발생 시 주문 차단 및 알림
- 10영업일 이상 무차이 증거

### 3.4 live promotion evidence가 없다

`promotion-evidence` 결과:

```json
{
  "status": "blocked",
  "blocked": 5
}
```

현재 요구 조건은 다음이다.

- DRY_RUN 30영업일
- PAPER 30영업일
- read-only reconciliation 10영업일
- 소액 주문 trial 1회 이상
- 수동 live promotion approval

코드만으로 이 조건을 채우면 안 된다. 실제 운용 증거가 필요하다.

### 3.5 24x7 heartbeat 증거가 부족하다

필요한 것:

- 30일 이상 연속 heartbeat

## 4. P1: 초거대 글로벌 운용을 위해 부족한 구조

### 4.1 글로벌 유니버스가 작다

코드상 global readiness는 tradable assets 10,000개 이상과 6개 이상 시장을 요구한다. 현재 runtime universe는 그 수준이 아니다. 모델 enum은 글로벌이지만, 실제 tradable universe는 아직 아니다.

필요한 것:

- KRX/US/EU/JP/HK/CN/EM 종목 마스터
- ETF/채권/옵션/선물/FX/원자재 계약 마스터
- 거래가능 여부, 휴장, tick size, lot size
- 상장폐지/거래정지/합병 이력
- 거래소별 시간대/세션/마감 규칙

### 4.2 자산군별 실전 리스크 모델이 부족하다

현재 Toss routeable scope는 KR/US 주식, ETF, 채권, 미국주식 옵션 중심이며 직접 futures, spot FX, direct commodities는 제외된다.

필요한 것:

- 옵션: Greeks, IV surface, exercise/assignment, 만기/권리 처리
- 채권: duration, convexity, yield curve, accrued interest
- 선물: margin, rollover, contract multiplier, expiry
- FX: spot/forward/swap, settlement, translation risk
- 원자재: contract roll, storage proxy, ETF tracking risk

### 4.3 포트폴리오 최적화가 아직 기본형이다

`StrategyEnsembleAllocator`는 전략 신호를 합치고 종목/섹터 cap을 적용한다. 하지만 초대형 퀀트 운용에는 부족하다.

필요한 것:

- 공분산 기반 최적화
- 리스크 패리티
- 변동성 타깃팅
- factor neutrality
- beta neutrality
- currency hedge ratio 최적화
- 거래비용/시장충격 반영 optimizer
- turnover constraint
- tax-aware rebalancing
- capacity-aware sizing

### 4.4 집행 엔진은 planner 수준이다

TWAP/VWAP/POV 계획은 있지만 LIVE_AUTO는 차단된다. 실제 child order manager와 fill loop가 없다.

필요한 것:

- child order 상태머신
- partial fill 대응
- cancel/replace
- venue/session별 주문 타입
- spread/volume/liquidity gate
- 주문 지연/거절/중복 방지
- broker disconnect recovery
- market access control

## 5. P2: 전략/리서치 수준에서 더 필요한 부분

### 5.1 전략 수보다 검증 깊이가 부족하다

현재 전략은 21개까지 늘었지만, 기관급 검증은 다음이 필요하다.

- walk-forward validation
- purged cross validation
- feature leakage 검사
- survivorship-bias-free backtest
- transaction cost / slippage / borrow cost / tax 포함
- regime별 성능 분해
- capacity 분석
- live paper drift 분석
- strategy decay 감지

### 5.2 ML/RL 알파 모델은 아직 없다

ML을 넣는다면 먼저 운영 인프라가 필요하다.

- feature store
- label 생성 규칙
- train/validation/test 시점 분리
- model registry
- online/offline feature consistency
- prediction drift monitoring
- explainability
- rollback
- 모델 과최적화 방지

### 5.3 이벤트/NLP 자동매매가 약하다

공시 이벤트 후보는 있지만 실시간 뉴스/NLP 자동 진입/청산은 아니다.

필요한 것:

- 실시간 뉴스/공시 stream
- earnings calendar
- consensus revision feed
- NLP sentiment/event extraction
- 중복 뉴스 제거
- 허위/오보 방어
- 장중 이벤트 risk limit

## 9. 최종 판단

Atlas Investment은 지금 “무인 글로벌 헤지펀드가 되기 위한 운영 OS”에 가까워지고 있다. 하지만 완성된 무인 초거대 글로벌 헤지펀드/퀀트는 아니다.

가장 큰 부족분은 전략 수가 아니라 다음 다섯 가지다.

1. 공식 실거래 브로커 API와 주문/체결 loop
2. 라이선스 있는 글로벌 데이터와 instrument master
3. 실계좌 reconciliation
4. 30일 이상 실제 무인 운용 증거
5. 포트폴리오 최적화/집행/리스크의 실시간 통합

이 다섯 가지가 채워지기 전에는 LIVE_AUTO 실주문은 계속 차단하는 것이 맞다.
