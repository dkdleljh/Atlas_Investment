# Atlas Investment 고도화 우선순위 제안

> 최신 기준(2026-05-31): Atlas Investment은 토스증권 공식 API 출시 전 안전한 PAPER/DRY_RUN 운용 OS입니다. 완성된 글로벌 헤지펀드 또는 실거래 봇으로 판정하지 않습니다. 토스 플랫폼 범위는 KR/US 주식·ETF·채권·미국주식 옵션 중심이며, 직접 선물·현물 FX·직접 원자재 거래는 공식 지원 전까지 제외합니다. 실거래는 공식 API adapter 구현, read-only reconciliation, 30일 heartbeat, promotion evidence 통과 후에만 검토합니다.

작성일: 2026-05-30

이 문서는 현재 Atlas Investment의 코드와 문서를 기준으로, 토스증권 공식 API 구현 전에도 더 고도화할 수 있는 부분을 정리한 것입니다.

## 결론

다음 단계의 핵심은 전략 개수를 늘리는 것이 아니라, 샘플 기반 골격을 실제 운용 가능한 플랫폼으로 끌어올리는 것입니다.

우선순위는 다음 순서가 좋습니다.

1. 실제 데이터 레이어
2. 포트폴리오/리스크 엔진 강화
3. 백테스트 신뢰도 강화
4. 자동 운영 루프
5. 전략 라이브러리 확장
6. 대시보드와 리포트
7. Toss API 연결 준비 세분화

## 1순위: 실제 데이터 레이어

현재 가장 큰 한계는 샘플 유니버스와 샘플 OHLCV에 의존한다는 점입니다.

고도화할 부분:

- 한국장 전체 종목 마스터 저장
- 미국장 전체 종목 마스터 저장
- ETF/ETN, 레버리지/인버스 자동 분류
- 거래정지, 관리종목, 상장폐지, 신규상장 상태 관리
- 실제 일봉 데이터 저장
- 실제 분봉 데이터 저장
- 환율 데이터 저장
- 데이터 품질 검사
- 결측치, 이상치, 액면분할, 배당, 병합 처리

추천 구현:

- `data/instruments/` 모듈 추가
- `data/prices/` 모듈 추가
- `data/quality/` 모듈 추가
- `data/vendors/` 공급자 어댑터 구조 추가

이 단계가 끝나야 백테스트 결과가 실제 의미를 갖습니다.

## 2순위: 포트폴리오/리스크 엔진 강화

현재 리스크 엔진은 기본적인 주문 차단과 익스포저 리포트 중심입니다. 기관급으로 가려면 포트폴리오 전체 위험을 더 정교하게 봐야 합니다.

고도화할 부분:

- 전략별 자본 배정 한도
- 시장별 한도: 한국, 미국
- 섹터별 한도
- 종목 상관관계 기반 집중도
- 변동성 기반 포지션 사이징
- 최대 낙폭 기반 자동 감속
- 일간/주간/월간 손실 한도
- 레버리지/인버스 총 비중과 단일 비중 분리
- 환율 노출 한도
- 주문 전후 예상 포트폴리오 비교

추천 구현:

- `risk/limits.py`
- `risk/position_sizing.py`
- `risk/correlation.py`
- `risk/drawdown_guard.py`
- `portfolio/rebalancer.py`

이 단계는 실거래 전 필수입니다.

## 3순위: 백테스트 신뢰도 강화

현재 백테스트는 단일 종목, 단순 체결, 단순 수수료/슬리피지 구조입니다. 전략을 평가하기에는 부족합니다.

고도화할 부분:

- 포트폴리오 단위 백테스트
- 여러 종목 동시 백테스트
- 월별/연도별 성과 분해
- 시장 국면별 성과 분해
- 매수/매도 체결 지연 모델
- 거래세/수수료/환전비용/미국장 세금 구조 반영
- 워크포워드 테스트
- 인샘플/아웃오브샘플 분리
- 과최적화 방지 리포트

추천 구현:

- `backtest/portfolio_engine.py`
- `backtest/costs.py`
- `backtest/walk_forward.py`
- `analytics/tear_sheet.py`

이 단계가 끝나야 전략을 실제 후보로 판단할 수 있습니다.

## 4순위: 자동 운영 루프

현재 CLI 명령은 수동 실행 중심입니다. 무인 자동화를 목표로 하려면 상시 실행 루프가 필요합니다.

고도화할 부분:

- 장 시작 전 준비 루틴
- 장중 감시 루틴
- 장 마감 후 리포트 루틴
- 한국장/미국장 시간대 구분
- 휴장일 캘린더
- 반복 실행 스케줄러
- 실패 시 재시도
- 장애 발생 시 자동 중지
- 매일 운영 리포트 자동 생성

추천 구현:

- `ops/scheduler.py`
- `ops/trading_calendar.py`
- `ops/healthcheck.py`
- `ops/recovery.py`
- `cli daemon` 명령

이 단계가 있어야 완전 무인 운용에 가까워집니다.

## 5순위: 전략 라이브러리 확장

전략 확장은 데이터와 리스크 기반이 어느 정도 잡힌 뒤 진행하는 것이 좋습니다.

고도화할 전략:

- 장기 추세 추종
- 스윙 모멘텀
- 변동성 돌파
- RSI/볼린저밴드 평균회귀
- 거래량 급증 전략
- ETF 자산배분
- 레버리지/인버스 헤지
- 환율 기반 미국장 비중 조절
- 실적 발표 전후 이벤트 전략
- 방어적 현금 확대 전략

초단타/스캘핑은 가장 나중입니다. 실시간 호가 품질, 주문 지연, API 제한을 알기 전에는 실제 전략으로 쓰기 어렵습니다.

추천 구현:

- `strategy/trend.py`
- `strategy/mean_reversion.py`
- `strategy/volatility_breakout.py`
- `strategy/asset_allocation.py`
- `strategy/hedge.py`
- `strategy/event.py`

## 6순위: 대시보드와 리포트

운용 시스템은 사람이 바로 상태를 확인할 수 있어야 합니다.

고도화할 부분:

- 현재 포트폴리오 요약
- 오늘 주문 후보
- 오늘 차단된 주문
- 전략별 성과
- 종목별 손익
- 시장별 익스포저
- 리스크 한도 사용률
- 운영 상태
- 장애 로그

추천 구현:

- `reports/daily_markdown.py`
- `reports/risk_dashboard.py`
- `reports/strategy_report.py`
- 향후 웹 대시보드 또는 정적 HTML 리포트

## 7순위: Toss API 연결 준비 세분화

토스증권 공식 API가 아직 공개되지 않았으므로 실제 구현은 불가능하지만, 연결 준비는 더 구체화할 수 있습니다.

고도화할 부분:

- REST 클라이언트 인터페이스
- WebSocket 클라이언트 인터페이스
- 인증 토큰 갱신 구조
- 요청 재시도 정책
- Rate limit 대응
- 주문 idempotency 정책
- 주문 상태 reconciliation
- 체결 이벤트와 내부 포지션 동기화

추천 구현:

- `brokers/toss_rest_client.py`
- `brokers/toss_websocket_client.py`
- `brokers/order_reconciliation.py`
- `execution/idempotency.py`

공식 문서가 공개되면 이 인터페이스에 실제 엔드포인트를 채우면 됩니다.
