# 실거래 수준 전략 확장 및 한계 기록

> 최신 기준(2026-05-31): Atlas Investment은 토스증권 공식 API 출시 전 안전한 PAPER/DRY_RUN 운용 OS입니다. 완성된 글로벌 헤지펀드 또는 실거래 봇으로 판정하지 않습니다. 토스 플랫폼 범위는 KR/US 주식·ETF·채권·미국주식 옵션 중심이며, 직접 선물·현물 FX·직접 원자재 거래는 공식 지원 전까지 제외합니다. 실거래는 공식 API adapter 구현, read-only reconciliation, 30일 heartbeat, promotion evidence 통과 후에만 검토합니다.

작성일: 2026-05-31

## 1. 요청

주인님 요청은 세 가지였다.

1. 기존 전략들을 전부 실거래 수준으로 업데이트
2. 실제 글로벌 퀀트/헤지펀드 기법을 찾아보고 실거래 수준으로 구현
3. 관련 문서를 친절하고 상세하게 작성

이번 작업의 중요한 원칙은 하나다. **실거래 수준의 코드 골격과 승격 기준은 강화하되, 공식 브로커 API·실시간 호가·실시간 체결·미체결 정정/취소가 없는 상태에서 실주문 가능 상태라고 속이지 않는다.**

## 2. 참고한 실제 운용 분류

전략 분류는 다음 공개 자료를 기준으로 삼았다.

- HFR Hedge Fund Strategy Classification: Equity Hedge, Event Driven, Macro, Relative Value를 큰 축으로 제시한다.
  - https://www.hfr.com/hfr-indices/hfr-hedge-fund-strategy-classifications/
- AQR style premia 자료: Value, Momentum, Carry, Defensive, Trend, Volatility 같은 스타일 프리미아를 체계적으로 다룬다.
  - https://www.aqr.com/Insights/Research/Journal-Article/Understanding-Style-Premia
  - https://www.aqr.com/Insights/Research/White-Papers/Understanding-Alternative-Risk-Premia
- SEC Market Access Rule 15c3-5: 자동화 주문 접근에는 사전 리스크 통제와 감독 절차가 필요하다는 기준을 제시한다.
  - https://www.sec.gov/rules-regulations/2011/06/risk-management-controls-brokers-or-dealers-market-access
- FINRA Market Access Controls: pre-trade threshold, 문서화, 정기 리뷰, 한도 집계 등 시장접근 통제 사례를 설명한다.
  - https://www.finra.org/rules-guidance/guidance/reports/2017-report-exam-findings/market-access-controls

위 자료를 그대로 복제한 것이 아니라, Atlas Investment의 현재 제약 조건에 맞춰 **PAPER/DRY_RUN 가능한 전략·검증·리스크 게이트**로 변환했다.

## 3. 이번에 추가한 코드

### 3.1 전략 플러그인 확장

파일: `src/atlas_investment/strategy/plugins.py`

기존 11개 전략에 더해 다음 6개를 추가했다.

| 전략 이름 | 대응하는 실제 운용 기법 | 현재 구현 수준 |
| --- | --- | --- |
| `time_series_momentum` | CTA/Trend Following/시계열 모멘텀 | 일봉 기반 추세 추종, 변동성 조정 비중 |
| `cross_sectional_momentum` | 상대강도/크로스섹션 모멘텀 | 종목 간 상대 모멘텀 후보 |
| `low_vol_defensive` | Defensive/Low Volatility 스타일 | 저변동성·방어주 후보 |
| `stat_arb_mean_reversion` | 페어/통계적 차익거래 전 단계 | z-score 평균회귀 후보, 실제 pair hedge는 아직 별도 필요 |
| `equity_long_short_quality` | Equity Long/Short, Quality-Momentum spread | 롱/축소 후보. 실제 숏 레그는 브로커/규제 확인 전까지 금지 |
| `liquidity_market_making_simulation` | Market Making/Liquidity Provision | 호가 데이터 전까지 비주문 시뮬레이션 |

이제 전략 레지스트리에는 총 17개 전략이 들어간다.

### 3.2 전략 등록/별칭

파일: `src/atlas_investment/strategy/registry.py`

추가한 전략들을 `all_strategies()`에 등록했다. 또한 아래 별칭도 추가했다.

- `pairs_trading` -> `stat_arb_mean_reversion`
- `stat_arb` -> `stat_arb_mean_reversion`
- `market_making` -> `liquidity_market_making_simulation`
- `long_short` -> `equity_long_short_quality`

### 3.3 알고리즘 집행 계획

파일: `src/atlas_investment/execution/algorithms.py`

실제 글로벌 운용에서는 신호가 좋더라도 한 번에 시장가로 던지지 않는다. 주문을 여러 조각으로 나눠 시장 충격과 체결 리스크를 줄인다. 이번에는 다음 알고리즘의 **계획 엔진**을 추가했다.

- `TWAP`: 시간 균등 분할
- `VWAP`: 거래량 곡선 프록시 기반 분할
- `POV`: 목표 시장 참여율 기반 분할

현재 상태는 `PAPER`/`DRY_RUN`에서는 `simulated`, `LIVE_AUTO`에서는 `blocked`다. 이유는 명확하다.

- 공식 주문 API 없음
- 실시간 호가 없음
- 실시간 체결 이벤트 없음
- 미체결 정정/취소 API 없음
- 장중 주문 실패 복구 경로 미검증

따라서 지금은 **실거래 전 검증 가능한 집행 계획**까지만 제공한다.

CLI:

```bash
.venv/bin/python -m atlas_investment.cli algo-execution-plan --algorithm vwap --mode paper --symbol 005930 --slices 5 --limit 10
.venv/bin/python -m atlas_investment.cli algo-execution-plan --algorithm twap --mode live_auto --symbol 005930
```

### 3.4 전략 승격 게이트

파일: `src/atlas_investment/strategy/readiness.py`

전략이 존재한다고 바로 실거래로 쓰면 안 된다. 그래서 `StrategyPromotionGate`를 추가했다.

검사 기준:

- 전략 연구소 결과 존재 여부
- PAPER 후보 종목 수
- 최대낙폭 기준
- 거래 횟수 부족 여부
- 실시간 데이터가 필요한 전략인지 여부
- 숏/롱숏 브로커 지원이 필요한 전략인지 여부

특히 다음 전략은 실시간 데이터 없이는 승격을 막는다.

- `scalping_simulation`
- `liquidity_market_making_simulation`

다음 전략은 숏/대차/규제 확인 없이는 숏 레그 승격을 막는다.

- `equity_long_short_quality`

CLI:

```bash
.venv/bin/python -m atlas_investment.cli strategy-readiness --strategy scalping_simulation --max-symbols 4 --days 220
.venv/bin/python -m atlas_investment.cli strategy-readiness --strategy time_series_momentum --max-symbols 4 --days 220
```

## 5. 실거래 수준으로 강화된 부분

이번 작업에서 “실거래 수준”에 맞춰 강화한 것은 다음이다.

- 전략 수 확장
- 전략별 보유기간·손절·익절·목표비중 명시
- 변동성 기반 비중 조정 일부 반영
- 전략 승격 게이트 추가
- 실시간 데이터 필요 전략은 자동 차단
- 롱숏/숏 관련 전략은 브로커·규제 지원 전까지 승격 차단
- TWAP/VWAP/POV 집행 계획 추가
- LIVE_AUTO 알고리즘 집행은 공식 API 전까지 차단
- 테스트 추가

즉, 무조건 주문을 내는 코드가 아니라 **실거래로 올려도 되는지 판단하는 안전장치**를 함께 구현했다.

## 6. 아직 실거래 수준이라고 말하면 안 되는 부분

다음은 아직 완성이라고 말하면 안 된다.

### 6.1 진짜 스캘핑/초단타

필요한 것:

- 실시간 호가
- 체결 이벤트 스트림
- 미체결 조회
- 정정/취소 API
- 왕복 지연시간 측정
- 주문 큐
- 거래소별 호가 단위
- 체결 확률/슬리피지 모델
- 급변동 중단 조건

현재는 후보 생성과 승격 차단까지만 구현했다.

### 6.2 진짜 페어트레이딩/통계적 차익거래

이번 구현은 z-score 기반 단일 자산 후보까지다. 실거래 수준이 되려면 다음이 필요하다.

- pair universe 생성
- 공적분/상관/스프레드 안정성 검증
- 양쪽 레그 동시 주문
- 한쪽만 체결되는 legging risk 처리
- 숏 가능 여부 확인
- borrow 비용과 locate 실패 처리

### 6.3 진짜 Equity Long/Short

현재는 롱/축소/숏 후보 신호만 낸다. 실제 숏은 다음 전까지 금지한다.

- 브로커 공매도/대차 지원
- 계좌 권한
- 규제 조건
- locate/borrow 비용
- 숏 포지션 강제청산 리스크 통제

### 6.4 마켓메이킹

현재는 비주문 시뮬레이션이다. 실거래 마켓메이킹에는 다음이 필요하다.

- 실시간 bid/ask
- quote update
- inventory skew
- cancel/replace
- adverse selection 방지
- exchange fee/rebate 모델

## 8. 결론

Atlas Investment은 이번 작업으로 실제 글로벌 퀀트/헤지펀드에서 흔히 쓰는 큰 전략 축을 더 많이 수용하게 됐다.

- 기존: 기본 추세, RSI, 돌파, 장기 추세, 스윙, 스캘핑 시뮬레이션, ETF 리밸런싱, 팩터, FX 오버레이, 이벤트 후보
- 추가: 시계열 모멘텀, 크로스섹션 모멘텀, 저변동성 방어, 통계적 평균회귀, Equity Long/Short 후보, 마켓메이킹 시뮬레이션, TWAP/VWAP/POV 집행 계획, 전략 승격 게이트

그러나 현재 결론은 여전히 명확하다.

**실거래 주문 자체는 아직 켜면 안 된다.**

실거래 승격에는 토스증권 공식 주문 API, 실시간 호가/체결 스트림, read-only reconciliation, 30일 이상 heartbeat, PAPER 성과 기록, 수동 승인 기록이 필요하다. 이번 작업은 그 전 단계에서 전략과 집행·승격 기준을 훨씬 촘촘하게 만든 것이다.
